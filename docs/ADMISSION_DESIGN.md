# V4 finite sponsored admission — implementation and acceptance

Status: CODE IMPLEMENTED / LOCAL ADMISSION/DESTINATION CHECKS PASS / NOT DEPLOYED. M2 NOT ACCEPTED.

## Scope

This is a separate replacement deployment candidate. Existing V3 source, compiled bytecode, journals, quote links and public evidence remain unchanged. V4 is not wired into the current frontend or deployment scripts. Do not point old share links at it or reuse testnet-m2.json for it.

The sponsor controls a finite allowance of automation work. A merchant needs an unexpired grant before creating a quote. Credits are recorded in a separate admission ledger and are not ETH, USDC, a customer fee, or proof of remote reserves.

Base cannot synchronously read Lasna reserves. A nonzero fundingObservation is an explicitly trusted sponsor attestation reference, not an on-chain proof of funding. Real source and destination fee checks, conditional budget calculations, operator tooling and fresh public integration still need implementation/verification before this candidate is deployable.

## Implementation

- packages/contracts/admission/SettlioAdmission.sol: closed by default; immutable sponsor/escrow/capacity/lifetime/horizon/retry configuration; explicit merchant grants; finite lifetime allocation; timestamps; atomic slot accounting; bounded shared retries.
- SettlioEscrowV4.sol: all three creation methods require admission; failed creation rolls back credit consumption. Payment expiry/terms, exact-asset custody, callback permissions and cancellation priority are retained. All successful terminal outcomes close the ledger slot; duplicate callbacks cannot close it twice. Failed principal transfers roll back both state and capacity.
- Existing quote payments, cancellation, callbacks, merchant release and customer refund recovery remain usable while new admission is closed. Confirmation and policy retries share one counter/cooldown; cancellation never consumes it.
- claimRefund is a customer-only recovery for an already recorded RefundPending cancellation. It pays the same asset/amount, uses the existing reentrancy guard and liability accounting, and works without sponsor credits or network delivery. It cannot refund an uncancelled/released quote, pay a different caller, or transfer twice. This prevents finite retry allowances from permanently stranding a reserved refund after network failure. Normal Reactive refunds remain supported.
- SettlioCallbackV4.sol creates the new escrow/ledger and retains both callback authentication guards and separate fee custody.
- SettlioReactiveV4.sol preserves tested scheduler semantics with explicit policy version 4. It listens only to the configured new escrow. Constructor/configuration/subscriptions still need fresh live proof.

## Bounds and tradeoffs

For one new deployment, enforce:

- active destination quotes + unused granted credits <= maxActive.
- lifetime accepted quotes + unused granted credits <= maxLifetimeAdmissions.
- Every newly accepted refund cutoff is at most maxHorizon seconds after admission.
- Each quote has at most maxRetries participant retry signals, shared across confirmation and policy paths, spaced at least retryInterval.
- A consumed lifetime credit is never regenerated by closing a job. Sponsors cannot mint an unlimited sequence of short-lived quotes on the same deployment.

The lifetime bound also limits distinct admitted quote IDs that delayed source observations could place in the source queue. Destination concurrency alone would not bound that queue: a new destination slot can open before the previous terminal acknowledgement reaches Lasna. Capacity is not silently released merely because a deadline passes; successful expiry/refund/release is required. Manual-release bookings can occupy destination capacity until their merchant claims, even if the source is idle.

These are finite work-admission bounds, not a promise that any reserve amount buys successful delivery at arbitrary future gas prices. Source scan/request/attempt limits remain 8/2/6 with 60-second source backoff. Fee prices, surcharges, delays and failed calls still matter. Sponsor compromise, unsafe grant issuance and underfunding remain trust/operational risks. Credits are not permissionless merchant-paid automation. A renewable production funding model is future work.

No public configuration numbers have been chosen. Tests use small fixture values (capacity 2, lifetime 3 or 4, horizon 1000 seconds, retry cooldown 60 seconds, allowance 2) to exercise exhaustion. They are not deployment defaults or approved production limits.
